## 1. 本轮目标

- 从二元 `germany/allies` 主路径迁移到维多利亚多国家兼容架构。
- 首版至少能表达 Britain、France、Russia、Ottoman、Austria、Sardinia、Neutral。
- 移除主路径对 `Faction.opponent` 和固定 `germanAI/alliedPlayer` 的依赖。
- 保留旧阿登数据可加载，旧测试和 legacy case 不做破坏性删除。
- 修正中立地块 / region fallback 到 `.allies` 的问题。

## 2. 本轮非目标

- 不新增黑海危机完整地图；那是 v5.2。
- 不重写 UI 视觉；只允许必要显示名和兼容字段。
- 不迁移全部单位兵种；那是 v5.3。
- 不迁移工业经济；那是 v5.4。
- 不实现完整外交危机；那是 v5.5。
- 不接真实 LLM。
- 不做全项目重命名。

## 3. 当前关键风险

来自 v5.0 审计：

- `Faction.swift` 只有 `.germany` / `.allies`，且内置 `opponent`。
- `GamePhase.swift` 只有 `.germanAI` / `.alliedPlayer` / `.resolution`。
- `CommandValidator.phaseAllowsCommands` 固定 German AI / Allied Player。
- `CommandExecutor.executeEndTurn` 固定 Germany -> Allies -> Germany。
- `DataLoader.initialActiveFaction` 从旧 phase 推导 `playerFaction` / `aiFaction`。
- `RegionDataSet.toRegions()` 把 nil owner/controller fallback 到 `.allies`。
- `DiplomacyState` 已有 `CountryProfile` 基础，但默认仍是 Axis / Allied Coalition。

## 4. 架构边界

必须保持：

- `HexTile.controller` 是真实占领权威。
- `Division.coord` 是单位位置权威。
- `RegionNode.controller` 只能从 hex 聚合或由受控规则更新，不能替代 hex。
- `regionToTheater` 不作为运行时推进权威。
- `hexToTheater` / `hexToFrontZone` 仍是动态权威。
- 玩家和 AI 命令仍经 `Command` / `ZoneDirective` / `WarCommandExecutor` / `CommandValidator` / `RuleEngine`。
- Legacy Agent D 保留。

## 5. 推荐实现顺序

### 5.1.1 Faction 兼容扩展

推荐短期保留 `Faction` 名称作为规则控制方，并扩展 enum：

```text
legacy:
  germany
  allies

victorian:
  britain
  france
  russia
  ottoman
  austria
  sardinia
  neutral
```

要求：

- `displayName` 改为维多利亚兼容显示，legacy case 明确标注为 Legacy。
- 不再让 `opponent` 成为主路径；如保留，只能标注 legacy，并避免新代码调用。
- 给 `neutral` 明确 display name。
- 所有 switch 必须处理新增 case，不能用错误 fallback 把新势力归到 Germany / Allies。

### 5.1.2 通用 phase 和行动许可

目标：

- 保留旧 rawValue 解码兼容。
- 新增或映射通用 phase，例如 `humanAction`、`aiAction`、`resolution`。
- `phaseAllowsCommands` 不再用 `germanAI/alliedPlayer` 判断阵营。

可选策略：

1. 低风险策略：先保留旧 `GamePhase` case，并新增 helper：
   - `allowsCommands(for activeFaction: Faction, playerFaction: Faction?)`
   - `isActionPhase`
   - `legacyDisplayName`
2. 中风险策略：扩展 enum 加 `humanAction` / `aiAction`，DataLoader 兼容旧 rawValue。

禁止：

- 直接删除 `.germanAI` / `.alliedPlayer` 导致旧 JSON 不能解码。
- 在多个文件各自写一套 phase 判断。

### 5.1.3 外交关系规则集中化

新增或扩展集中规则函数，建议放在 `DiplomacyState` 或新小型 rules 文件中：

```text
isHostile(lhs: Faction, rhs: Faction, state: GameState) -> Bool
isFriendly(lhs: Faction, rhs: Faction, state: GameState) -> Bool
canAttack(attacker: Faction, target: Faction, state: GameState) -> Bool
canEnterTerritory(faction: Faction, controller: Faction?, state: GameState) -> Bool
```

要求：

- `neutral` 默认不可被当作任意一方收入或补给来源。
- `canAttack` 不能等价于 `lhs != rhs`。
- 旧 Germany / Allies 数据可以默认 atWar。
- Black Sea powers 初期可先建立基础 profile，不要求完整 DiplomaticPlay。

### 5.1.4 DataLoader 和 Region fallback

必须修：

- `RegionDataSet.toRegions()` 的 nil owner/controller fallback 到 `.allies`。
- DataLoader 对 neutral controller 的解析。
- 初始 active faction 不再由 `germanAI/alliedPlayer` 唯一推导。

可保留：

- 旧 `ardennes_v0_scenario` 作为 legacy 默认，直到 v5.2 引入黑海危机默认剧本。
- 阿登专项 `guderian` 校验只能在 `scenario.id == "ardennes_v0"` 时触发。

### 5.1.5 AppContainer / TurnManager

要求：

- `AppContainer` 不再只为 `.germany` 跑 AI。
- 建立 `shouldRunAI(for:)` 或等价判断。
- 保留 Mock / Marshal fallback。
- 不改变 `ZoneDirective -> WarCommandExecutor -> RuleEngine`。
